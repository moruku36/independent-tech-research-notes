# Kubernetes上の自律エージェントを封じ込める多層防御

## 概要

- プレプリント：Kubernetesを操作するAIエージェントの脅威モデルと参照アーキテクチャ。
- ツール境界の認可を中心に、ID、隔離、通信、秘密情報、実行時監視など7層の防御を提案する。
- 評価は脅威と対策の対応表および攻撃シナリオの定性的検討で、攻撃成功率や負荷の実測はない。

## 実務向けの読み解き（7行）

- 運用エージェントが読むログやチケットは、操作を誘導する入力になりうる。
- 論文はモデルが誘導されても、実行基盤の権限制御が効く設計を求める。
- ID、RBACとAdmission、実行隔離、通信、ツール仲介、データ、実行時監視の7層を整理する。
- EKS、AKS、GKEの対応例と、承認を要する操作の流れを示す。
- 実務ではツール引数の許可条件とKubernetes API側の制限を二重に設ける案が参考になる。
- まず読み取り専用の小さな構成で、禁止操作と外向き通信を試験したい。
- 提示された防御の有効性・遅延・費用は実測されていない。

## 方法・主張と証拠

10種類の脅威、9原則、7層の制御とガバナンスを整理し、EKS・AKS・GKEへの対応を示す。評価は脅威・制御マトリクスと4つの攻撃ウォークスルーで、実験方法を提案する設計研究。

## 限界・未確認点
