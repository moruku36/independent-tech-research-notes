# コーディングエージェントのツール呼び出しを狙う攻撃評価

## 概要
- **何か**：6種類のコーディングエージェントを対象にしたセキュリティ評価のプレプリント。
- **結果**：攻撃者が外部ツールを制御できる条件で、内部指示の流出やツール呼び出しの乗っ取りを調べた。
- **注意**：arXiv抄録の全組み合わせでの成功という記述と、本文表の一部0/10の結果は一致しない。

## 資料と確認範囲
Yuchong Xie、Mingyu Luo、Zesen Liu、Zhixiang Zhang、Kaikai Zhang、Yu Liu、Zongjie Li、Ping Chen、Shuai Wang、Dongdong She、[Red-Teaming Coding Agents from a Tool-Invocation Perspective: An Empirical Security Assessment](https://arxiv.org/html/2509.05755v6)、arXiv:2509.05755v6、2026年6月28日改訂（初版2025年9月6日）。2026年11月3日（日本時間）に一次HTMLの抄録、脅威モデル、評価表、対策・限界の主要部分を確認。PDF・攻撃コード・製品の現行状態は未確認、再現未実施。

## 課題と方法
外部ツールの説明や戻り値は、通常はタスクに使うデータである。著者らは、攻撃者が悪意ある外部ツールへ接続させ、その説明と戻り値を操作できるという前提で、内部指示の流出と、内蔵のコマンド実行ツールの悪用を評価した。攻撃者はモデルの重みや内蔵ツールを直接変更できないという設定。6製品と複数モデルの組み合わせを調べた。

## 結果と未解決の不一致
arXiv書誌抄録は、内部指示の漏えいが25組み合わせ中19で起き、コード実行が全てのテスト対象の組み合わせで起きたと記す。一方、本文HTMLの抄録・導入は漏えい指標で最良だった組み合わせを18/25と記し、これは漏えいの有無とは異なる指標である。また**表5の新しい構成**には二段階の攻撃でも0/10の欄があり、例えば新しいClaude Codeの掲載対象は0/10である。arXiv抄録の「全組み合わせで成功」と表はそのままでは整合せず、条件や版の差の説明は未確認。成功率は各セル10試行であり、製品の現行版全体の安全性を示さない。

## 実務への応用案
MCPなどの外部ツールは提供元・更新経路・必要権限を確認し、説明や戻り値を信頼できない入力として扱う。実行環境を隔離し、秘密へのアクセスと外向き通信を制限し、重要な操作は明示的な承認や決定的な権限検査を設ける。安全な評価環境で異常な引数や指示をテストする。これらは防御提案で、論文による本番効果の保証ではない。

## 限界
攻撃者が悪意ある外部ツールに接続させられる前提、選ばれた製品・モデル・設定と小数の試行に依存する。著者らは成功を意図したコマンドツールの呼び出しで測っており、OSやネットワークの制限が異なる環境で実害が生じる保証はない。製品は更新されうる。独立検証・再現・導入未実施。
