# AgentCap：ツール境界での実行時認可

## 概要

- **何についてのものか** モデルが提案するツール呼出しを、モデルの外側で認可する研究。
- **何を述べているか** MCPラッパーが方針を検査し、短期・回数制限付きの実行権限を検証する。
- **留意点** 攻撃成功ゼロは指定評価での結果。有用性の低下と方針の網羅性にも制約がある。

## 実務向けの読み解き（6行）

- 意図、前提手順、両立しない権限、引数の出所を検査する。
- 委任は行為・対象を維持し、有効期間と予算を狭める方向だけを認める。
- GPT-5.4は評価した2ベンチマークで攻撃成功率ゼロ。
- GPT-4oでは攻撃が残り、正常タスクの達成率にも低下がある。
- 各モデル・ベンチマーク条件は1回の実行で、分散の推定はない。
- 応用案は、模擬ツールの決定的な入口で範囲・出所・委任を検証すること。

## 書誌・確認範囲

Aravinda Kashyap Kabbinamakki Suresh、Peng Gao『AgentCap: Capability-Based Runtime Authorization for Secure LLM Agent Execution』。arXiv:2611.00729v1、2026-10-31。2026-11-15 JSTに§3〜4・6を部分確認。非アーカイバルなワークショップ採択はarXiv記載で、独立確認は未実施。

## 証拠・限界

AgentDojoは正常97課題・攻撃949件、InjecAgentは攻撃1,054件と構成した正常例を使う。認可方針はアプリケーションの仕様。未拘束の引数、出所ラベルの漏れ、文章による影響が残りうる。永続記憶・文脈をまたぐ出所と、別管理主体への委任は今後の課題。
