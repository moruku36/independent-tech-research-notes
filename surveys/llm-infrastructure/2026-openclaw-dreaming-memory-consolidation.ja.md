# OpenClaw Dreaming：根拠付きの外部記憶を整理・昇格する

- OpenClawの公式製品文書。日々の記録から長期記憶へ情報を移すDreamingの構成と制約を説明する。
- Light・REM・Deepの段階を経て、根拠付き候補を選び、長期記憶の更新を検証・記録する。
- 外部記憶の更新であり、モデルの重み学習ではない。実装説明は性能向上や秘密情報保護の実証とは別である。

## 実務向けの読み解き（7行）

- 情報の収集、振り返り、長期記憶への採用を分ける設計として読む。
- 生成した振り返り文を、次の記憶の根拠として循環利用しないことが重要になる。
- 出典・時点・置き換え関係を持たせ、元の情報が変わった場合の確認を設計する。
- 記憶の書き換え前の保存と差分は、誤った更新の調査や復元に役立つ。
- ログに秘密が入る経路は、記憶の品質確認とは別に検討する。
- 自分のハーネスでは整理の前後を固定し、検索だけの場合との品質・総費用を比較する案がある。
- 今回は文書確認のみで、OpenClawの設定変更・定期実行・モデル呼び出しは行っていない。

## 問い・仕組みと証拠

セッションをまたいで役立つ情報を、どのように整理し長期記憶へ昇格するかを扱う。文書ではLightとREMが候補・反省を準備し、Deepが閾値と元資料の再確認を経てMEMORY.mdへ反映する。更新前の内容はSQLite側に保存し、DREAMS.mdは人が読む記録であって昇格元にしない。

信頼由来がuntrusted／systemの候補を除外し、構造化した更新判断、出典参照、既存項目の損失上限、文脈予算を検証する仕組みを説明する。ただし会話の取り込み前に秘密情報をマスクしないと明記する。既定で有効とされる機能でも、選択したメモリープラグインと導入版で利用範囲が異なる。

## 限界と本ノートの評価

比較ベンチマークやこの利用者の環境での改善率は示されていない。構造的な由来チェックと、内容の真偽・秘密情報の除去・悪意ある指示の完全検出は別の問題である。文書の既定値を、実際の端末の状態として扱わない。

自分のagent-sleep-labへの応用として、採用候補、根拠、旧版、差分、採用しなかった理由を残す設計が参考になる。ただしこの読書作業では、別リポジトリの設計や稼働設定を変更していない。
