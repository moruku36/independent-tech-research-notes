# Unsloth Qwen3.8：量子化とローカル実行

## 概要

- **何についてのものか** Qwen3.8のローカル推論ガイド。今回は27Bのdenseモデルを中心に整理する。
- **何を述べているか** GGUF・NVFP4と、11月11日のDynamic V3.1更新を説明する。
- **留意点** 必要メモリと品質は、量子化、文脈長、配信条件に依存する。

## 実務向けの読み解き（6行）

- Qwen3.8-27Bは視覚・推論に対応し、最大256K文脈と説明する。
- 4bit版の表は16〜19GBで、単位は合計メモリまたは共有メモリ。
- 最大文脈・最大同時実行時のピーク容量を保証する値ではない。
- Dynamic V3.1の品質比較には、文脈予算とサイズ集計の条件がある。
- NVFP4の手順はBlackwell向けで、GGUFという別の実行経路もある。
- 応用案は、量子化を選ぶ前に同じ課題で品質・ピーク容量・遅延を測ること。

## 書誌・確認範囲

Unsloth『Qwen3.8 – How to Run Locally』。2026-11-15 JSTに27B要件、Dynamic V3.1、実行手順を部分確認。他モデルの節は今回の対象外。更新される文書であり、グラフと元の実行結果は独立監査していない。

## 証拠・限界

主要比較グラフは埋め込み層のサイズを除き、全文では実際のディスク・RAM使用量を別途論じる。エージェント評価は256K、その他は128K文脈。5〜10%という品質改善は提供元の報告として扱い、集約方法が未確認のため一律の改善とは読まない。
