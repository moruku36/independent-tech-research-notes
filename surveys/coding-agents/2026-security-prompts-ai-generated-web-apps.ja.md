# 生成Webアプリ400本で見るセキュリティ指示とスキャナー検出

## 概要

- AIコーディングの指示にセキュリティ要件を加えたときの効果を調べた統制実験のプレプリント。
- 生成した400アプリでは、追加指示ありの推定検出件数が35%減り、直接依存の宣言が増えた。
- 結果は特定の自動スキャナーの検出に基づく。追加指示に伴う機能や依存関係の変化も効果に含まれる。

## 実務向け6行

- 固定した100仕様を、コーディング支援ツール2種と指示2条件で実装し、計400アプリを比較した。
- OWASPに沿った要件を追加すると、調整後のアプリあたり検出件数は35%減った（発生率比0.65、95%信頼区間0.60～0.71）。
- アプリ自身のコードの高重大度検出はほぼ半減した。直接依存が増え、依存関係に由来する高重大度の勧告件数は増えた。
- Node.jsの集計では直接依存の宣言数が概ね2倍になった。直接依存数で割った勧告率は上昇しなかった。
- 検出結果の全面的な人手判定はなく、対象のツール、仕様、スキャナーが適用範囲を決める。
- 応用案。セキュリティ要件と合わせて新規依存を確認し、重大な検出については人が内容を確認する。

## 根拠と限界

- 各仕様はツールと指示の組み合わせにつき1回生成された。全体の発生率比はツール、複雑さ、使用言語で調整している。繰り返し生成によるばらつきは別途確認が必要。
- アプリあたりの勧告件数は宣言する依存の数の影響を受ける。依存数あたりの勧告率と自作コード由来の検出件数は、それぞれ別の観点を表す。
- 要件追加で生成される機能、依存の選択、スキャナーからの見え方が同時に変わり得る。この設計では指示の文言だけの寄与は切り出せない。

## 応用・無料の確認案

提案・未試行。管理下の少数の生成アプリを既存の防御用スキャナーで比較し、自作コードと依存関係の検出を区別する。追加パッケージを記録し、検出の一部をアプリの管理者と確認する。
