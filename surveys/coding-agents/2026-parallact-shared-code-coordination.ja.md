# ParallACT：共有コードで独立した依頼を調整する

## 概要

- **何についてのものか** 共有リポジトリで別々の依頼を受ける2つのコーディングエージェントを評価するベンチマーク。
- **何を述べているか** 独立した並行作業で統合後の正しさが下がり、順番に引き継ぐと差の多くを回復する。
- **留意点** 調整を必要とする課題を選んでおり、単体オラクルには両方の要件を渡す。

## 実務向けの読み解き（6行）

- ParallACTは相補的な要件と、衝突する要件の組を含む。
- 統合パッチを、結合テストまたは両要件のテストで採点する。
- Claude Opus 4.8の衝突課題は、単体オラクル62%に対し、互いを知らない並行構成16%。
- 同条件でメッセージ付きは20%、順次引継ぎは54%だった。
- 診断用の衝突例であり、通常開発で衝突が起きる頻度を示すものではない。
- 応用案は、インターフェースの担当、共有前提、両要件の受入テストを管理すること。

## 方法・証拠・限界

Claude Code・Opusは衝突50組を含む85問、オープンウェイトとハーネスの6構成は155問を使う。構成内の比較は同じ問で行う。実効トークン費用は各オラクルに対する比で、構成間では部分集合と費用の数え方に注意する。2エージェントと小規模な診断用データの結果。

## 無料の確認計画・活用状態

提案・未実施。無料の小さなローカルリポジトリに2つの変更依頼と、組み合わせた動作のテストを作る。順次・並行の比較を計画し、インターフェース決定、担当の連絡、統合失敗、トークン、時間を記録する。要件とテストを固定し、両依頼を見た時点を明示する。次はデータの作り方と費用の定義を確認してから、今のハーネスでの改善幅を評価する。
