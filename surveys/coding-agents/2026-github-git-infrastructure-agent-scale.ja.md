# GitHubのエージェント規模向けGit基盤

## 概要

- **何についてのものか** エージェントとCIが並行して使うリポジトリ基盤についてのGitHub技術記事。
- **何を述べているか** 永続ストレージ、配信用ワーカー、参照更新の合意処理を分離する設計を示し、内部測定で最大35倍の書き込みスループットを報告する。
- **留意点** 進行中の基盤開発を扱う記事。測定条件と一般環境での効果には追加の根拠が要る。

## 実務向けの読み解き（6行）

- エージェントの頻繁なチェックポイントと並行pushで、書き込み負荷と待ち時間の影響が増す。
- マージは共有の参照に集まり、CIは読み出しを一斉に増やす。
- 合意が必要な範囲を参照更新に絞り、保守処理を別ワーカーへ移す設計。
- 正本をAzure Blob Storageに置き、キャッシュ付きワーカーで読み出し能力を増減させる。
- ハーネスへの応用案は、pushの遅延、fetchの量、マージ待ちを別々に測ること。
- 最大35倍は内部測定の書き込みスループットで、作業全体の改善幅は負荷に依存する。

## 設計・証拠・限界

現行構成では、完全なリポジトリ複製が読み出し能力と書き込み時の調整を結び付けていると説明する。新構成はストレージと計算資源の独立した拡張、保守処理の分離、合意を取る書き込み経路の縮小を目指す。活動件数には人と自動化の両方を含み、エージェントだけの因果寄与は測っていない。
