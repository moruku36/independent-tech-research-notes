# SKILL-SIF：カーネル監査スキルの限界と失敗からの改善

- Linuxカーネルの既知脆弱性を対象に、公開セキュリティスキルとコーディングエージェントを評価するプレプリント。
- 37スキル・4モデル・100件で14,800実行を比較し、失敗から手順を改訂するSKILL-SIFも調べる。
- 修正対象ファイルを教えた評価であり、未知の大規模コード全体の監査や誤検出率をそのまま表す結果ではない。

## 実務向けの読み解き（7行）

- スキルを渡すだけで正確な監査になるとは考えず、根拠の取得と確認手順を見る。
- 関数、原因となる文、脆弱性クラスの一致を別々に評価する。
- 自分の監査では、候補を却下する条件と未確認の疑問を残す仕組みを検討する。
- 最終報告に根拠や位置が引き継がれるかも確認対象にする。
- 失敗から改訂した手順は、改訂に使わなかった課題で検証する。
- 改善倍率だけでなく、絶対成功率、悪化した課題、確認に必要な費用を見る。
- 本ノートの確認案は未実施で、カーネル監査・スキル実行・重み更新は行っていない。

## 問い・方法・報告結果

修正前のソースと対象ファイルを与え、ネット・Git履歴を使わずに調べる。完全正解はCWE、関数、原因文の同時一致で、全実行の11.1%。単なる「問題あり」の判定とは異なる。

上位5スキルを失敗の分析から改訂し、別の100件で比較する。完全正解の集計は6.05%から11.20%。最大8倍は特定の組み合わせの2%から16%であり、全スキルの改善倍率ではない。元の14,800実行と改訂比較は母集団が違う。改訂するのはスキル手順で、モデル重みではない。

## 限界と本ノートの評価

既知の脆弱性と場所の手がかりがある設定から、通常のコードでの偽陽性やゼロデイ発見率は推定できない。対象言語・CWE・モデル・スキル選抜・正解注釈に依存する。スキルなしとの差をこの集計だけから断定しない。

失敗分類をそのまま人の能力不足に読み替えず、手順の欠落とモデルによる実行の失敗を分ける。自分のハーネスでは、改訂前後の差分と不成功も保存し、別課題へ一般化するか確認する必要がある。
