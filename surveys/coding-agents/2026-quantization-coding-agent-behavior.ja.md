# 量子化で変わるコーディングエージェントの解き方

## 概要

- プレプリント：4ビット量子化がコーディングエージェントの正答率・実行過程・失敗に与える影響を比較する。
- 補正後に有意な正答率低下は検出されなかったが、ツール利用と失敗の種類はモデルごとに変化した。
- 115問のPython競技課題と一つの実行ループによる評価で、性能同等や実運用の高速化を証明したものではない。

## 実務向けの読み解き（7行）

- 量子化後のコーディングエージェントを、最終的な正解数だけで評価してよいかを問う研究。
- Qwen2.5-Coderの3サイズとDevstralを、BF16・AWQ・GPTQで比較した。
- 多重比較補正と問題単位の分析では、統計的に有意な正答率低下を検出しなかった。
- 一方、Qwen-7Bは量子化後に一発で解く例が減り、実行して直す解き方が増えた。
- 本ノートの応用案：採用前にツール呼び出し回数、失敗種類、総遅延も記録する。
- 検出されなかった差を性能同等の証明とせず、必要な品質水準で追加評価したい。
- 他の言語・実装や実運用の費用への一般化は未検証。

## 研究の問い

4ビット重み量子化は、実行フィードバックを使うコーディングエージェントの正答率と行動をどう変えるか。

## 手法・データ・比較条件

Qwen2.5-Coder-Instruct 7B/14B/32BとDevstral-Small-2507 24BをBF16、W4A16 AWQ、GPTQで比較。OJBenchのEasy・Medium計115問、Pythonのみ、3 seed、最大5回のツール呼び出しを使う。Hardは全構成0%のため集計対象外。統計分析は多重比較補正と問題内のseed相関を考慮する。

## 主張と証拠

表1ではQwen-32Bの平均正答率がBF16 13.91%、AWQ 10.72%と名目上低下するが、補正後には有意差を検出しない。解決経路と失敗分布には変化があり、論文は正答率だけでは行動を説明できないと結論する（§3–5、付録A）。

## 限界・妥当性への脅威

一つのベンチマーク、Python、一つの実行ループ、限られたモデル群。正解数が少なく、検出力の限界がある。「有意差なし」は同等性試験の成立を意味しない。遅延・実使用メモリーなどの総合効率の評価は今後の課題。
