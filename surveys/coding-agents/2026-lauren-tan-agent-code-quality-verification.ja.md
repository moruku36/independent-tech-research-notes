# All Code Is Slop：コーディングAIを支える制約と検証

## 概要

- **何か**: Lauren Tanによる、AIを使う開発で品質を保つためのAI Engineer CODE 2026講演。
- **主張**: 自動化を広げる前に、コードの設計・実行可能なチェック・検証へ投資する。
- **注意点**: チームの成果は登壇者の自己報告で、文字起こしの誤認識や因果評価の不足がある。

## 実務向けの読み方（7行）

- 問いは、コードを書く量を増やしながら品質を保つにはどうするかという点。
- 設計と静的チェックを土台とし、実行時・形式検証、判断が必要な文章の規則を重ねる。
- APIの利用制限、Electronのプロセス境界の強制、利用者目線の機能マップを例示する。
- チームで月約11,000件のPR、相対的なrevert率が約0.5%と報告する。
- 応用案は、繰り返す指摘を検査可能な制約にし、古い悪い手本も取り除くこと。
- レビュー案は、差分と動作の証拠を、明示した受入条件で確認すること。
- PR数とrevert率だけでは、保守性・欠陥の不在・自動マージの普遍的な安全性は示せない。
