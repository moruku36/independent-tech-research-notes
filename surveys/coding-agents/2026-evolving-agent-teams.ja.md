# Evolving Agent Teams：停滞に合わせてAIチームを組み替える

## 概要
- **何か**：GPUカーネル最適化などで、AIエージェントの役割・協調方法を動的に変える実験プレプリント。
- **結果**：著者らは、予算を揃えた4種類のGPUカーネル課題で、提案手法が単一コーディングエージェントを上回ったと報告する。
- **注意**：試行回数は少なく、固定チームの結果と使用モデルの記述に不一致がある。実用環境への一般化は未確認。

## 資料と確認範囲
Shiyi Cao、Ziming Mao、Dacheng Li、Joseph E. Gonzalez、Ion Stoica、[Evolving Agent Teams](https://arxiv.org/html/2610.36848v1)、arXiv:2610.36848v1、2026年10月27日公開。2026年11月1日（日本時間）に一次HTMLの抄録、手法、主な実験、結論、付録の一部を確認。[著者のコード](https://github.com/caoshiyi/EAT)は論文にリンクされているが、コード・PDFの内容確認と再現は未実施。

## 課題と方法
GPUカーネルの性能探索では、初期の改良後に設計が行き詰まり、難しい別の設計を試せないことがある。提案手法では監督役が停滞の原因を診断し、実装、性能解析、知識統合などの役割や協調方法を組み替える。共有ファイルシステムに学習メモ、各チームの成果物、変更履歴を残し、次の構成に引き継ぐ。メイン実験はClaude CodeとClaude Opus 4.6を使用し、H100・B200上の4課題を評価した。

## 結果と条件
- 予算を揃えたMLA decodeの比較では、著者らは単一Claude Codeが約0.44〜0.51倍、提案手法が約0.75倍と報告する。比較対象はFlashInferの本番カーネルで、1倍未満はそれより遅い。課題・実験条件に限定された結果である。
- **追加予算**を使った別の実行では、H100上のFlashInfer-Benchの47ワークロードに対する速度比の幾何平均が約1.21倍となり、36件で基準より速かった。残り11件は0.86〜0.99倍。47件の正しさのテストを通ったと著者らは報告する。予算を揃えた比較とは分けて読む。
- 速度は各ワークロードの基準実行時間÷候補実行時間の幾何平均。FlashInfer側の計画処理の扱いで比較値が変わり、図1では計画処理を除く基準に対して0.96倍と記す。
- 主要な各条件は2回実行して良い方を報告し、固定チームとCodexの比較は各1回。追加事例も各1回で、統計的な結論には限界がある。

## 原文内の未解決の不一致
- 固定4役チームのMLA性能は、序論では **0.55倍**、4.5節では **0.31倍** と記される。差の原因は未確認。
- 4.1節は固定チームを **Opus 4.7**、提案手法を **Opus 4.6** と記す一方、4.5節は両者が同じモデルを使うと述べる。役割変更だけの効果と断定できない。
- G+AllReduceの追加予算結果も、4.2節では **1.49倍**、4.3節では **1.56倍** と記載される。条件差の説明は確認できず、未解決のまま残す。

## 実務への応用案
自宅ラボやAIチームでは、停滞時に「原因の切り分け→必要な役割の追加・変更→結果の記録」を小さく試せる。実験メモに失敗理由、変更点、性能、コストを残し、単一エージェントと同じ予算で比較する。権限・秘密情報・承認・監査は別途設計する。これらは提案であり、論文はクラウド運用での有効性を検証していない。
