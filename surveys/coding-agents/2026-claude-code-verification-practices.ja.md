# Claude Codeの検証：チェックの信頼性と実行の証拠

## 概要

- **何についてのものか**: Addy Osmaniが説明する、Claude Codeチームの検証の実践記事。
- **何を述べているか**: 振る舞いの検査と保護されたレビュー規則で、証拠に基づく委譲を支える。
- **留意点**: チームの実践・自己報告であり、効果を因果的に示す比較研究ではない。

## 実務向け6行

- 問いは、変更が実際に動くことをエージェントがどう示すか。
- 記事はE2E・プロパティ・差分テストを説明する。
- レビュー規則は、判定対象の変更ではなく信頼できる版から読む。
- 応用案は、実装前に利用者から見た受入条件を決めること。
- 過去の不具合と正常な変更で、検証器の見逃し・誤警報も測る。
- 紹介されたコミットゲートには例外があり、常に閉じる安全保証ではない。

## 書誌・確認範囲

Addy Osmani、claude.dev、2026年11月16日公開。2026年11月18日 JSTに本文と公式Code Reviewカスタマイズ文書を確認。実践記事・関連仕様の一部を読了。内部データや実装の独立監査はしていない。

## 根拠と限界

実アプリでの確認、差分に応じた信頼性チェック、過去の障害を使う検証器評価を組み合わせる。強制前の観測モードや繰り返しブロック時の例外も記載されるため、検証操作の記録を、合格必須のゲートと取り違えない。

公式文書では、Code ReviewサービスのREVIEW.mdはbase・defaultブランチから読み、保護設定によって挙動が変わる。また、ローカルの/code-reviewはREVIEW.mdではなくCLAUDE.mdを読む別機能。設定は実際に使うレビュー製品と対応させる。

## 応用・無料の確認案

提案／未試行。ローカルの小さな題材で、過去の不具合、正常な変更、意図した仕様変更を一つずつ選ぶ。速い振る舞いの確認、必要な不変条件、適切なら新旧比較を用意する。期待結果は判定対象から分離し、結果をコミットに結び付ける。誤警報・見逃し・時間・例外・証拠を記録する。合格のために失敗テストを消さず、廃止時も理由と代替の検査範囲を残す。

活用状態：提案／未試行／未採用。この記事の追加では、モデル呼び出し・環境変更・実験を実施していない。
